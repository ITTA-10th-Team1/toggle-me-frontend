# 메인 방 발표 버전

대표 태그는 RoomPresentationConfig에서 거울 `데님`, 냉장고 `빵`을 제공합니다. 라우터가 발표 설정을 RoomScreen에 명시적으로 전달하며, RoomScreen 기본값은 빈 목록입니다. 태그 UI는 클릭 동작 없이 가로 표시하고 최대 5개를 표시합니다. 실제 분석 결과가 없을 때 샘플로 대체하지 않습니다.

실제 대표 태그 API는 아직 미정입니다. 카테고리별 이미지 3장 이상, 최근 최대 10장 분석, 카테고리당 대표 태그 1개, 분석 중/실패 시 마지막 유효 결과 유지, 기존 결과 없으면 미표시, 숨긴 가구의 카테고리도 조건 충족 시 표시라는 정책을 백엔드와 연결해야 합니다.

기존 계정의 로그인 응답이 DONE이면 메인 방 경로로 이동합니다. 인증 서버 연결이나 신규 회원의 프로필/가구 선택을 생략하는 구현은 아닙니다. 로그인은 실제 서버를 사용하며 `API_BASE_URL` 설정과 서버에 등록된 계정이 필요합니다. 자동 테스트에서만 가짜 응답을 사용합니다. 핀보드는 아직 담당 팀원의 실제 화면 연결이 필요합니다.

거울·냉장고는 발표용으로 고정 배치합니다. widthUnits/heightUnits와 API renderOrder로 GLB 크기나 깊이 순서를 변경하지 않습니다. 모델은 앱에 포함한 전체 방 GLB를 한 번 읽고, stand/body 노드의 메시 터치로 카테고리를 구분합니다.

일반 시작 화면은 온보딩입니다. 발표에서 방으로 바로 진입하려면 다음처럼 실행할 수 있습니다.

```powershell
flutter run --dart-define=ROOM_DEMO_ENTRY=true
```

로그인 PR #11의 카카오 설정을 사용하는 경우 기존 `--dart-define-from-file=dart_defines.json` 옵션도 함께 유지합니다. 이 파일의 실제 키는 커밋하지 않습니다.

로그인 API PR #20과 소셜 친구 목록 PR #22가 병합된 main을 반영했습니다. 병합된 로그인 처리·모델·검사 코드는 유지하고 공통 UI 사용 부분만 통합했습니다. 별도로 만들었던 AccountApi, 공통 토큰 갱신 클라이언트, 방 API repository는 포함하지 않습니다. 로그인 후 PROFILE/FURNITURE 화면 분기는 로그인 PR에서 미완료로 남긴 상태를 유지합니다.

소셜 친구 목록은 현재 가짜 데이터를 사용하며, 놀러가기는 임시로 내 방 경로로 이동합니다. 상대 회원 ID 기반 방문과 실제 소셜 API 연결은 후속 작업입니다.
