# 메인 방 렌더링

## 모델

- 앱 에셋: `assets/models/toggleme_room.glb` (책상 포함, `desk-02-center`)
- 디자이너의 책상 포함 GLB 메시·재질·바이너리는 유지합니다. 기존 12개 노드의 위치·회전·크기는 이전 배포 모델로 복원했습니다.
- `stand`(거울)와 `body`(냉장고)는 기존 배치를 유지합니다.
- 책상·의자·추가 선반을 새 부모 노드 `desk` 아래 묶었습니다. 세 부분 모두 책상 터치, 배치, 숨김을 함께 적용합니다.
- 크기가 메시 정점에 반영되어 두 가구의 노드 scale은 `(1,1,1)`. 서버 배치 연동 시 이전 모델의 배율을 다시 적용하지 않아야 함.

## 책상 서버 등록

- 정확한 카탈로그/배치 값은 `docs/desk-backend-layout.json`에 있습니다. 제안 가구 ID·디자인 ID는 각각 3, 코드는 `desk`, 노드 이름도 `desk`입니다.
- 위치: `(-1.0408016920089722, 0.385222852230072, -0.021670036017894745)`, 회전 quaternion `(0,0,0,1)`, scale `(1,1,1)`, renderOrder `3`.
- 책상 내부 자식 노드에 디자이너의 회전·크기를 보존했습니다. 부모 `desk`에 자식의 배율/회전을 다시 넣지 마세요.
- 가구 type·variant를 ACTIVE로 등록하고 기존 방의 1층에도 책상을 추가해야 합니다. 거울·냉장고의 배치와 숨김은 수정하지 않습니다. 이미 사용자가 숨긴 책상도 덮어쓰지 않습니다.
- 원본 데스크톱 GLB에는 부모 `desk`가 없으므로 앱에는 이 PR에 포함된 처리 모델을 사용합니다.
- 회원 방은 서버에서 배치된 가구만 표시합니다. 책상 미등록/숨김 상태에서는 모델을 표시하지 않고 기록 카테고리 선택도 차단합니다. 게스트 미리보기는 세 가구를 보여줍니다.
- 기록 카테고리는 서버의 실제 방 가구 ID를 사용합니다. 제안 ID 3이 이미 사용 중이면 백엔드에서 다른 ID를 정해도 프론트가 응답값을 사용합니다.
- 새 기록 API는 필요하지 않습니다. 기존 업로드·분석·아이템 저장/조회 API가 활성 `desk` 타입을 받아야 합니다. 책 추천 전용 기능(`bookshelf`)은 이 변경에 포함하지 않습니다.

## 화면 설정

- `RoomLightingConfig`: 환경 `legacy`, 노출 1, 그림자 강도 0.75·부드러움 1.
- 그림자는 방 전체의 접지감을 보완하며 가구별 내부 그림자를 생성하지 않음.
- 고정 카메라와 가구 터치 유지.
- 하단은 기록하기와 네 기능 버튼을 하나의 배경으로 연결.
